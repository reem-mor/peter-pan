# INC-2401 — checkout DB connection pool exhaustion (2026-06-18)

**Severity:** P1 · **Duration:** 34 min · **Class:** resource_exhaustion

**What happened:** the checkout service began returning 503s at 09:14 as its
database connection pool saturated at 100% utilization. A background reconciler
deployed that morning opened a connection per order row and never released it on
the error path, so a burst of retryable payment failures leaked the pool dry
within minutes. Healthy request threads then blocked on connection-acquire
timeouts and cascaded into upstream latency.

**Detection:** pool-utilization alert (T+3m) and a connection-acquire timeout
spike on the checkout dashboard. **Resolution:** rolled back the reconciler
deploy and raised the pool ceiling temporarily (T+31m); utilization drained and
503s cleared within four minutes of rollback.

**Lessons:**
- The leak lived on an error path with no test coverage — added a pool-usage
  assertion to the reconciler's integration suite.
- Connection-acquire timeouts now page before the pool hits 100%, not after.
- Reused the db-connection-pool runbook; the "compare pool size to recent
  deploys" step pointed straight at the culprit.
