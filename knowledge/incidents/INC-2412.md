# INC-2412 — expired TLS certificate on the payments gateway (2026-06-22)

**Severity:** P1 · **Duration:** 27 min · **Class:** availability

**What happened:** the payments gateway started rejecting all inbound TLS
handshakes at 02:00 with certificate-expired errors. The leaf certificate had a
90-day lifetime and the automated renewal job had silently failed nine days
earlier when its ACME account key rotated — no alert fired on the failed
renewal, so the expiry was the first visible symptom. Every downstream service
calling the gateway saw connection failures, not slowness.

**Detection:** synthetic-probe TLS handshake failure (T+1m); the certificate
expiry monitor had a 7-day warning threshold that never fired because the metric
exporter was scraping the wrong endpoint. **Resolution:** issued and deployed a
fresh certificate manually (T+24m), then repaired the renewal job's account key.

**Lessons:**
- Alert on *renewal-job failure*, not just on days-to-expiry — a broken renewer
  is the leading indicator.
- Certificate expiry monitoring must probe the live listener, not a config file.
- See the cert-rotation runbook; the manual re-issue path held up under pressure.
